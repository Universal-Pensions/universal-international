### Root cause: every teardown delete is fire-and-forget

Nineteen teardown deletes across eight spec files. **Not one checks the returned `error`, and not
one asserts the row is gone:**


The PostgREST client returns `{ data, error }`; it does not throw. A delete that is refused —
by a `BEFORE DELETE` trigger, a guard function, a policy — resolves successfully with
`error != null`, and the test reports green. The `rls-isolation` case is the clean demonstration:
its teardown is a `finally` block running two deletes in sequence, and the **second** one succeeded
(no `emp-e2e-foreign-*` row survives, `employers` is exactly the 8 real rows) while the **first**
did not — `s-e2e-emp-foreign-1785752999757` is still there with its `employer_id` nulled by the
`ON DELETE SET NULL` from the employer that *was* removed. A checked error would have failed that
run loudly on 2026-08-03; instead it has been silently wrong for three weeks.

Note the contrast that proves the pattern is fixable: `subscriber-signup-to-contribute.spec.ts`
routes its cleanup through `cleanupSubscriberByPhone()` (FK-aware) in **both** `beforeEach` and
`afterEach`, and it has leaked **nothing** — the subscriber-count histogram above shows no signup
residue at all.

### Remedy

1. Check the error on every teardown call: `const { error } = await …delete()…;
   expect(error, 'teardown: subscribers').toBeNull();` — in an `afterAll`/`finally` an
   `expect` failure still marks the run failed, which is the point.
2. Add a suite-level `globalTeardown` that sweeps `id LIKE 'tst-%' OR id LIKE '%-e2e-%' OR
   name ~* '^(TST|E2E)'` across `subscribers`, `agents`, `branches`, `employers`, `distributors`
   and fails the run if it deleted anything — a leak detector, not just a mop.
3. Add the returns-to-baseline assertion the config comment already claims is true
   ("The DB itself was verified clean — it returns to baseline exactly after a run"):
   snapshot `count(*)` for the 8 mutable tables in `globalSetup`, re-read in `globalTeardown`,
   assert equality. Nothing in the repo does this today.
